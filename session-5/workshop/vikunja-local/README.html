התקנת Vikunja מקומית עם Docker

כל משתתף מריץ עותק נפרד במחשב שלו. Ollama ממשיך להפעיל את המודל; Vikunja מספק את לוח המשימות. אין צורך במחשב שרת משותף או בחשבון Vikunja Cloud.

החבילה כוללת compose.yaml מוכן. הוא מפעיל את היישום בגרסה 2.7.1, מאפשר גישה מאותו מחשב בלבד ושומר נתונים בתיקיות ליד קובץ ההפעלה. SQLite כבר כלול ביישום.

הכינו לפני השיעור: Docker Desktop פעיל, חיבור לרשת להורדת התמונה הראשונה ותיקיית עבודה שניתנת לכתיבה. מדריך זה נבדק מול התיעוד הרשמי; Docker אינו מותקן בסביבת הכנת החומרים, ולכן ההתקנה והפקודות לא הורצו אצלנו על Windows או macOS.

1. מתקינים ומפעילים Docker Desktop

Windows

  1. פתחו את מדריך Docker הרשמי ל־Windows. בדקו התאמה לדרישות מערכת ההפעלה, WSL 2 ו־virtualization, והורידו את המתקין המתאים למחשב.
  2. הריצו את המתקין. במסלול WSL 2 ודאו שהאפשרות פעילה. אם נדרשת הפעלה מחדש או הכנת WSL, השלימו אותה לפי ההוראות הרשמיות לפני המשך.
  3. הפעילו Docker Desktop מתפריט Start והמתינו שמנוע Docker יהיה פעיל. משתמשים בקונטיינרי Linux.
  4. פתחו PowerShell חדש והריצו את בדיקות הגרסה הבאות.

macOS

הורידו Docker Desktop עבור Apple silicon או Intel לפי סוג המחשב, בהתאם למדריך macOS הרשמי. גררו ל־Applications, פתחו את Docker והמתינו להפעלתו. לאחר מכן פתחו Terminal.

# בודקים שפקודת Docker זמינה ושיש חיבור למנוע
 docker version
# בודקים שרכיב Compose זמין
 docker compose version

הצלחה: פקודת version מציגה גם Client וגם Server, ללא שגיאת חיבור למנוע. המילה Server כאן מתייחסת למנוע המקומי של Docker; אין שרת כיתתי משותף.

2. מפעילים את Vikunja מהקובץ שסופק

חלצו את חבילת הסטודנטים במלואה. פתחו מסוף מתוך התיקייה Session5/workshop/vikunja-local, שבה נמצא compose.yaml. ב־Windows אפשר לפתוח את התיקייה בסייר הקבצים ולבחור Open in Terminal. ודאו שלא נוצר בטעות קובץ בשם compose.yaml.txt.

Windows · PowerShell

# בודקים שנמצאים ליד קובץ ההפעלה שסופק
 Get-Item compose.yaml
# מכינים תיקיות שיישארו על המחשב
 New-Item -ItemType Directory -Force data/db, data/files
# בודקים שהגדרות Compose תקינות
 docker compose config
# מורידים את גרסת היישום שהוגדרה בקובץ
 docker compose pull
# מפעילים ברקע את העותק המקומי
 docker compose up -d
# רואים אם היישום פועל
 docker compose ps

macOS · Terminal

# בודקים שנמצאים ליד קובץ ההפעלה שסופק
 ls compose.yaml
# מכינים את תיקיות הנתונים המקומיות
 mkdir -p data/db data/files
# בודקים את ההגדרות ומורידים את התמונה
 docker compose config
 docker compose pull
# מפעילים ובודקים מצב
 docker compose up -d
 docker compose ps

פתחו בדפדפן http://localhost:3456. הכתובת מיועדת למחשב שלכם בלבד. ההפעלה הראשונה עשויה להימשך יותר זמן בגלל הורדת התמונה והכנת מסד הנתונים.

הצלחה: פקודת ps מציגה את השירות במצב ריצה, והדפדפן מציג את Vikunja. פקודת Docker שעברה ללא שגיאה אינה מספיקה בלי פתיחת היישום.

3. יוצרים חשבון ופרויקט תרגול מקומיים

  1. בעמוד המקומי בחרו הרשמה וצרו חשבון תרגול. זהו חשבון במופע שלכם, לא הרשמה לענן של Vikunja.
  2. צרו פרויקט תרגול בשם שתבחרו. השתמשו בנתונים סינתטיים.
  3. צרו משימה אחת, למשל ״בדיקת שמירת נתונים״. היא תשמש לבדיקה שהלוח והאחסון פועלים.
  4. אם המשתמש או הפרויקט כבר קיימים מהפעלה קודמת, התחברו אליהם במקום ליצור כפילות.

4. איפה הנתונים נשמרים?

במחשב שלכםבתוך הקונטיינרמה נשמר?
data/db/dbקובץ SQLite עם משתמשים, פרויקטים ומשימות.
data/files/app/vikunja/filesקבצים מצורפים ליישום.

הנתיבים יחסיים לתיקיית compose.yaml. התיקיות נמצאות מחוץ לקונטיינר; החלפת קונטיינר אינה אמורה למחוק אותן. מחיקת תיקיות הנתונים עצמן תמחק את המידע, ולכן שומרים את תיקיית התרגול.

# עוצרים את היישום בלי למחוק את תיקיות הנתונים
 docker compose stop
# מפעילים שוב את אותו יישום
 docker compose start

רעננו את הדפדפן ובדקו שהמשימה שיצרתם נשארה. זו בדיקת השמירה הנדרשת לפני השיעור.

לגיבוי תרגול פשוט, עצרו את היישום, העתיקו את compose.yaml ואת כל תיקיית data למיקום גיבוי, ואז הפעילו שוב. אין להעתיק רק קובץ SQLite בזמן כתיבה ולכנות זאת גיבוי שנבדק.

למי שעובד ב־Linux

לפי התיעוד, התמונה פועלת כברירת מחדל עם מזהה משתמש 1000. הכינו את תיקיות data/db ו־data/files עם הרשאות מתאימות למשתמש הזה לפני הפעלה. המדריך הכיתתי הראשי הוא Windows/macOS; ראו את הוראות ההרשאות הרשמיות.

5. מחברים את ה־MCP המובנה

Vikunja כולל MCP מגרסה 2.7.0. אין צורך לבנות שרת חדש כדי לקרוא את לוח המשימות.

  1. ביישום המקומי פתחו את תפריט המשתמש ואז Settings → MCP.
  2. צרו אסימון בשם שתזהו, כגון ״תרגול מקומי״. לבדיקת קריאה התחילו בהרשאת Read only ובחרו הרשאות בהתאם לפעולה.
  3. העתיקו את כתובת החיבור ואת הוראות הלקוח מתוך המסך. שמרו את האסימון במקום המיועד לו בתצורת החיבור; אין להכניס אותו לפתק או להודעת המודל.
  4. כתובת ה־MCP של ההפעלה שבקובץ היא http://localhost:3456/api/v2/mcp.
  5. חברו לקוח מקומי שתומך ב־Streamable HTTP ובאסימון Bearer. לדוגמה, ב־Claude Code משתמשים בפקודה שהיישום מספק, עם הכתובת המקומית.
# מחליפים YOUR_LOCAL_TOKEN באסימון המקומי לפי מסך MCP
 claude mcp add --transport http --header "Authorization: Bearer YOUR_LOCAL_TOKEN" vikunja-local "http://localhost:3456/api/v2/mcp"

בתוך Claude Code בדקו את החיבור עם /mcp. בקשו את פרטי פרויקט התרגול ואת משימותיו והשוו ללוח בדפדפן. אין לבצע שינוי רק כדי להוכיח שהחיבור קיים; כתיבה היא שלב נפרד עם הרשאות ואישור מתאימים.

Jarvis: החיבור ל־Claude Code אינו מחבר אוטומטית את Jarvis. הוא זקוק ללקוח MCP משלו ולתצורת הכתובת והאסימון. מסלול זה צריך להיות מוכן ונבדק מול פרויקט Jarvis שבו עבדתם. תרגיל 3 אינו דורש Vikunja: בו בונים שרת ליכולת שתבחרו.
