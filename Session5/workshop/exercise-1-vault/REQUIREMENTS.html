יוצרים מסמכי צוות וגורמים ל־Jarvis לענות מתוכם

בסוף התרגיל תשאלו את אותו Jarvis מהמפגש הקודם על פרט שכתבתם היום. התשובה צריכה לכלול את הפרט הנכון ולהפנות לפתק שבו כתבתם אותו.

לפני שמתחילים

עובדים עם Obsidian, עם Claude Code ועם פרויקט Jarvis שכבר פעל אצלכם במפגש הקודם. ממשיכים את היישום הקיים. Ollama והמודלים שבהם השתמשתם צריכים להיות מוכנים.

יש כאן שני מקומות עבודה.
בתיקיית הכספת כותבים את הפתקים. בתיקיית פרויקט Jarvis משנים את הקוד שקורא אותם. בכל שלב נציין באיזו תיקייה עובדים.
  1. פתחו ב־Obsidian כספת חדשה, למשל Team-notes. שמרו את הנתיב המלא שלה.
  2. מצאו את תיקיית Jarvis מהמפגש הקודם ואת פקודת ההפעלה שכבר עבדה אצלכם. השאירו אותה זמינה לחלון העבודה השני.
  3. בחרו פרויקט ושתי פגישות סינתטיות משלכם, או השתמשו בכרטיסי העובדות המצורפים. בחרו שמות ותאריכים שמתאימים לסיפור שלכם.

התחילו מבדיקת הפעלה של Jarvis. במקרה של תקלה פנו למרצה כדי להכין את נקודת ההתחלה. תוצר הסיום כולל כספת ותשובה מתוכה.

צרו את הקבצים הבאים. שמות הפרויקט והפגישות לבחירתכם; שמות התיקיות עוזרים להפריד בין מקורות לבין טיוטות.

  • כרטיס הפרויקט: מה מטרתו, מי מעורב בו ואילו שאלות נשארו פתוחות. הוסיפו קישורים לשתי הפגישות.
  • שני סיכומי פגישות: כתבו תאריך, מה דווח, מה הוחלט ומה צריך לעשות בהמשך. ציינו מי אחראי כשזה ידוע והשאירו מידע חסר גלוי.
  • תבנית: הכינו כותרות שישמשו אתכם לפגישה הבאה. לצדה כתבו שני סיכומים מלאים.
  • טיוטה: כתבו נוסח קצר שממתין לבדיקה וסמנו אותו בבירור כטיוטה.
  • תחום החיפוש: ב־indexing-scope.md כתבו שה־RAG יקרא רק מתוך Projects ו־Meetings. הטיוטות, התבניות ותיקיית ההגדרות של Obsidian יישארו מחוץ לחיפוש.

בכרטיס הפרויקט ובשני סיכומי הפגישות הוסיפו project_id זהה. בשני הסיכומים הוסיפו גם meeting_date. אפשר לעשות זאת דרך Properties של Obsidian; במדריך הטכני מופיעה גם דוגמה לכתיבה בראש הקובץ.

הוסיפו לאחד הסיכומים פרט בדיקה שרק הצוות שלכם יודע, למשל: ״שם בדיקת הכיתה: אורן־צוות־7״. סמנו אותו כפרט מלאכותי לבדיקת השליפה.

עבודה עם Claude Code: בקשו ממנו להציע את המבנה ואת נוסח הפתקים, בדקו אותם מול העובדות, ואז בקשו ליצור אותם בכספת. בדקו ב־Obsidian שהפתקים נפתחים וששני הקישורים מכרטיס הפרויקט עובדים.

חיבור תיקיית הכספת דרך MCP ב־Windows

פתחו PowerShell בתוך תיקיית הכספת. Node, npx, Claude Code ומחבר הקבצים מוכנים לפני השיעור. הריצו:

claude mcp add --transport stdio --scope project team-files -- npx -y @modelcontextprotocol/server-filesystem "$($PWD.Path)"
claude

בתוך Claude Code פתחו /mcp. לאחר החיבור בקשו: ״הפעל דרך team-files את list_allowed_directories״. ודאו שהנתיב שהוחזר הוא הכספת שלכם. אם מופיע נתיב רחב יותר, פנו למרצה לפני עריכת קבצים. פקודות macOS/Linux ופירוט החיבור.

מה צריך לראות: כספת משלכם עם שישה קבצים, שני סיכומים שונים, קישורים עובדים ופרט בדיקה חדש באחד הפתקים.

2. מחברים את הכספת לאותו Jarvis · דקות 18–30

כעת עברו לחלון עבודה שני, בתוך תיקיית פרויקט Jarvis. הפתקים נשארים בכספת; כאן משנים את הקוד שטוען אותם.

פתחו שם את Claude Code ומסרו לו את הנתיב המלא של הכספת. בקשו:

״אנחנו ממשיכים את Jarvis שכבר עובד כאן. מצא את הקוד שטוען מסמכים ואת האינדקס שהיישום משתמש בו. התאם את מקור המסמכים לכספת שבנתיב שאמסור. קרא רק Projects ו־Meetings, ושמור לצד הקטעים את נתיב הקובץ, תאריך הפגישה ומזהה הפרויקט. השתמש בתשתית החיפוש הקיימת. הראה לי מה השתנה ומה הפקודות המדויקות לרענון האינדקס ולהפעלת אותו Jarvis.״

בדקו את השינוי והריצו את פקודת הרענון שמתאימה למאגר שלכם. זהו השלב שבו מעבירים את מסמכי הכספת למסלול החיפוש של Jarvis.

מה צריך לראות: קטע מתוך הפתק החדש מופיע במאגר החיפוש עם הנתיב והתאריך שלו. השוו את הקטע שבחיפוש לתוכן שמופיע ב־Obsidian.

3. שואלים ובודקים · דקות 30–40

  1. הפעילו את Jarvis בפקודת ההפעלה שכבר עבדה אצלכם, עם השינוי שביצעתם.
  2. פתחו שיחה נקייה ושאלו: ״מה שם בדיקת הכיתה שתועד בפגישה? ציין מקור״. השאירו את הערך עצמו בפתק בלבד; השאלה תבקש מ־Jarvis למצוא אותו.
  3. השוו את התשובה לפתק. בדקו גם את הערך וגם את ההפניה למקור.
  4. שנו את הערך בפתק, רעננו שוב את האינדקס ושאלו בשיחה נקייה. התשובה צריכה להתעדכן.

מה צריך לראות: אותו Jarvis מחזיר את הפרט מהפתק שלכם עם מקור, ואחרי רענון מחזיר את הגרסה החדשה.

סיימתם כאשר

  • יש כספת שיצרתם עם שני סיכומים וקישורים עובדים.
  • רק תיקיות המקור שבחרתם נכנסות לחיפוש.
  • Jarvis עונה נכון על פרט שלא הופיע בשאלה ומפנה לפתק המתאים.
  • שינוי הפרט ורענון האינדקס משנים את התשובה בהתאם.

אם נתקעתם

חסרה תשובה מהפתק החדש? בדקו שהנתיב נכון, שהפתק נמצא ב־Meetings או ב־Projects, ושהרענון עדכן את האינדקס שאותו Jarvis באמת קורא. התשובה נשארה ישנה? רעננו ונסו שיחה נקייה. זקוקים לעזרה בזיהוי פקודת ההפעלה? עצרו ובקשו מהמרצה לעזור לזהות את פרויקט Jarvis שלכם.

המדריך הטכני המלא מיועד לפרטי התקנה ואבחון. לתרגיל עצמו השתמשו בפרויקט Jarvis שלכם ובפקודות שמצאתם בו.

שני בונוסים · אחרי השלמת התרגיל

1. תשובה שמחברת שלושה פתקים

פזרו בין שלושה פתקים את מטרת הפרויקט, החלטה ותנאי לביצועה. שאלו שאלה שמחייבת את שלושתם. בדקו שהתשובה מחברת את המידע ומפנה לכל המקורות. הסירו מקור אחד מהחיפוש והריצו שוב: המידע החסר צריך להישאר חסר.

2. איזו החלטה עדיין בתוקף?

כתבו החלטה ישנה ופתק מאוחר שמחליף או מבטל אותה במפורש. שאלו מה ההחלטה שבתוקף. התשובה צריכה להסביר את ההחלפה ולצרף את שני המקורות והתאריכים. בססו את ההחלפה על ניסוח מפורש בפתק המאוחר, וצרפו את תאריכי שתי ההחלטות.
