בונים שרת FastMCP ליכולת שבחרתם

בחרו פעולה או תהליך שמועילים לפרויקט הצוות. הגדירו ובנו שרת עם 3–5 כלים, הפעילו אותו מקומית ובדקו אותו באמצעות לקוח MCP. אין חובה לבנות חיבור ל־Vikunja, ל־RAG או לאפליקציה מסוימת.

התרגיל משתמש בחבילה העצמאית fastmcp==4.0.0 ובייבוא from fastmcp import FastMCP. מכינים סביבה נפרדת לפני השיעור; אין לערבב בה את סביבת MCP SDK v1 מהדוגמאות הישנות.

מה בוחרים ומה מוסרים ל־Claude Code?

  1. נסחו צורך במשפט: מי המשתמש, מה הוא רוצה לבצע ומה תהיה הוכחת הצלחה.
  2. בחרו מקור שכבר נגיש לכם: פונקציה, קובץ מקומי, נתוני תרגול או API שכבר הוכן. אין צורך להתחיל התקנת מוצר חדש.
  3. פרקו ל־3–5 פעולות משלימות. לכל כלי כתבו שם, תיאור, שדות קלט, תוצאה ומקרה כשל.
  4. החליטו אם נדרש State. אם כן: מה נשמר, לפי איזה מזהה, לכמה זמן ומה קורה אחרי הפעלה מחדש. אם לא, הסבירו מדוע כל קריאה עומדת בפני עצמה.

אפשר לבקש: ״התאם את starter.py לצורך שבחרנו. בנה את הכלים לפי ההגדרות שלנו, עם טיפוסים, תיאורים ובדיקות קלט. שמור מידע חסר גלוי, והוסף בדיקות הצלחה וכשל. הסבר בעברית כל שורת קוד. אל תוסיף חיבור לחשבון או פעולה חיצונית שלא הגדרנו.״

הכנה לפני השיעור

נדרש Python 3.10 ומעלה; דוגמת המרצה נבדקה ב־Python 3.12. פתחו PowerShell בתיקיית התרגיל והריצו:

# יוצרים סביבה נפרדת לחבילה העצמאית
py -3 -m venv .venv
# מתקינים את הגרסה שנבדקה לפני תחילת זמן התרגיל
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# בודקים את דוגמת המרצה דרך MCP אמיתי
.\.venv\Scripts\python.exe verify_example.py

ב־macOS/Linux: יוצרים סביבה עם python3 -m venv .venv ומשתמשים ב־.venv/bin/python במקום נתיב Windows. הרצת macOS/Python 3.12 נבדקה בפועל; פקודות Windows תואמות מבנה venv אך טרם נוסו ב־Windows.

קבצים ותפקידם

  • example_server.py — דוגמה קטנה מלאה: בדיקת כותרת ומטרה של משימה. אינה שומרת משימה ואינה שופטת את איכות הניסוח.
  • starter.py — נקודת התחלה פתוחה. החליפו שמות, חתימות ותיאורים לפי הפעולות שבחרתם והשלימו את ה־TODOs.
  • inspect_server.py — לקוח בדיקה לשרת שתבחרו, לגילוי קטלוג ולהפעלת כלי.
  • verify_example.py — בדיקות מוכנות של דוגמת המרצה בלבד; אינן מאשרות אוטומטית את מקרה השימוש שלכם.
# מגלים את הקטלוג שהשרת שלכם מפרסם
.\.venv\Scripts\python.exe inspect_server.py --server starter.py
# מפעילים את כלי הדוגמה עם קובץ קלט שנמסר בחבילה
.\.venv\Scripts\python.exe inspect_server.py --server example_server.py --tool validate_task_brief --arguments-file example-input.json

לכלי שלכם צרו קובץ JSON מתאים ושנו את שם הכלי ואת נתיב הקלט בפקודה. התוצאה מציגה is_error, נתונים ותוכן. שדה עסקי valid=false הוא תוצאה תקינה שמדווחת על בעיה בתוכן; שדה חובה שלא נשלח גורם לשגיאת קלט דרך MCP.

הפעלה וחיבור ללקוח

קובץ השרת מסתיים ב־mcp.run(transport="stdio"). בהרצה לבדו הוא ממתין ללקוח; אינו פותח שיחה. לקוח הבדיקה המצורף מפעיל אותו כתהליך.

כדי לחבר ל־Jarvis או ל־Claude Code מגדירים בכל לקוח את פקודת Python מהסביבה ואת הנתיב המלא לשרת הצוות. חיבור לאחד אינו מחבר את האחר. הוספת לקוח MCP ל־Jarvis תלויה בגרסת הפרויקט ויש להכינה ולבדוק אותה בנפרד. אל תציגו קריאת לקוח בדיקה כאילו המודל המקומי כבר בחר בכלי.

בהפעלת stdio אין להדפיס הודעות רגילות ל־stdout של השרת. השתמשו בלוגים מתאימים או ב־stderr; stdout שמור לפרוטוקול.

State אינו רכיב שחייבים להוסיף לכל שרת. אם הפעולה מקבלת כל מה שנחוץ בבקשה ומחזירה תוצאה, אפשר להשאירה ללא תלות בקריאות קודמות. אם נדרשת שמירה, בדקו גם מה קורה אחרי הפעלה מחדש.

שני בונוסים למתקדמים — מחוץ ל־40 דקות הליבה

בונוס 1: מצב מתמשך ושחזור

הוסיפו תהליך קטן שיוצר טיוטה עם מזהה ושומר אותה בקובץ. הפעילו מחדש את השרת, קראו את הטיוטה לפי המזהה והוכיחו שהתוכן נשמר. הגדירו תחום קבצים מפורש ומדיניות למזהה שאינו קיים.

בונוס 2: כשל וניסיון חוזר

דמו כשל אחרי ביצוע פעולה מקומית ולפני החזרת תשובתה. הוסיפו מזהה פעולה ובדיקה של תוצאה קיימת, כדי שניסיון חוזר לא ישכפל קובץ או רשומה. בדקו הצלחה, כשל וחזרה עם אותו מזהה; שינוי תוכן תחת אותו מזהה דורש התנהגות מוגדרת.

בדיקת הסיום

  1. הצוות מסביר איזה צורך השרת פותר ומדוע הכלים מתאימים לו.
  2. בקטלוג מופיעים 3–5 כלים עם שמות, תיאורים וסכמות נכונים.
  3. לפחות פעולה אחת הודגמה מקצה לקצה ונבדקה מול קלט או מקור.
  4. מקרה כשל מוחזר בבירור, ללא נתוני הצלחה מומצאים.
  5. מדיניות State ברורה ונבדקה בהתאם לדרישה.
