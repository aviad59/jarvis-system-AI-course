תרגיל 1 — הכנת המסמכים לחיפוש: Indexing

נבנה את השלב הראשון של סוכן עזר לטיפול בתקלות: מסמכים → chunks עם מקור וגרסה → embeddings → index מקומי בקובץ JSON.

מה תקבלו בסוף?

קובץ שבו כל רשומה שומרת chunk, metadata וה־embedding שלו. תוכלו לפתוח רשומה ולראות את הטקסט המלא, את מסמך המקור ואת המספרים שהחזיר מודל ה־embeddings.

החיפוש לפי שאלת משתמש יתווסף בתרגיל הבא. כאן בונים ובודקים את המידע שישמש אותו.

המסמכים והאירועים מומצאים לצורכי תרגול. כל שאלה עתידית על ״האירוע הנוכחי״ מתייחסת ל־28 באוקטובר 2026 בשעה 09:26.

בחרו מסלול embeddings אחד

מסלול מקומי ומסלול ענן זמינים לכל המשתתפים. מי שלא הכין מודל מקומי יכול לבחור בענן. השתמשו באותו ספק ובאותו מודל לכל ה־index; השאלה בתרגיל החיפוש תעבור דרך מודל תואם.

א. מקומי — Ollama עם embeddinggemma

  1. התקינו את Ollama לפי האתר הרשמי ופתחו את היישום.
  2. בדקו אילו מודלים כבר קיימים:
ollama list

אם embeddinggemma חסר, פקודת ההכנה היא:

ollama pull embeddinggemma

הפקודה מורידה מודל ודורשת רשת ומקום פנוי. מבצעים אותה לפני השיעור. לאחר ההכנה:

python preflight.py --provider ollama
python preflight.py --provider ollama --sample

ההרצה הראשונה מציגה LOCAL MODEL READY. השנייה מפעילה את המודל על דוגמה אחת ומציגה REAL EMBEDDING VERIFIED; DIMENSIONS: 768 עבור גרסת embeddinggemma הרגילה. הממדים בפועל נקראים מתשובת המודל.

ב. ענן — Voyage AI API

ל־Anthropic אין שירות embeddings משלה; Anthropic ממליצה על Voyage AI, ולכן מסלול הענן משתמש בו. נדרשים מפתח API של Voyage AI (אישי או ארגוני), הרשאת שימוש ותקציב API זמין. במסלול זה אין הורדת מודל למחשב. בקשות embeddings עשויות להיות בתשלום לפי תנאי החשבון.

בדיקת הכנה מבקשת מפתח בהקלדה מוסתרת:

python preflight.py --provider voyage --ask-key

יופיע CLOUD KEY PRESENT. זה בודק שיש ערך למפתח. כדי לבדוק בפועל גישה ויצירת embedding אחד:

python preflight.py --provider voyage --ask-key --sample

המודל במסלול זה הוא voyage-3.5 (תומך גם בעברית). הדוגמה תציג את מספר הממדים שהוחזר. המפתח נשמר בזיכרון התהליך בלבד. בהרצה הבאה תתבקשו להקליד אותו שוב. מי שכבר הגדיר VOYAGE_API_KEY בסביבת העבודה יכול להשמיט את --ask-key.

Claude Code עוזר לכתוב ולהריץ את התוכנית. את ה־embeddings מחשב Ollama או Voyage AI API, לפי המסלול שתבחרו. Claude (Anthropic API) משמש בתרגיל 3 ליצירת התשובה, לא ל־embeddings. מנוי לכלי כתיבת קוד אינו מחליף הרשאה לספק embeddings.

3. הכנת הקטעים וה־metadata

python build_index.py prepare

הפלט מציג שמונה מסמכים ואת מספר הקטעים מכל אחד, ולאחר מכן PREPARED: documents=8, chunks=.... מספר הקטעים תלוי במימוש שלכם. התוצר הוא build/chunks.json.

בדקו רשומה לפני חישוב embeddings:

python inspect_index.py build/chunks.json --record 1
python inspect_index.py build/chunks.json --html build/chunks-view.html

פתחו ב־VS Code את build/chunks.json, או פתחו בדפדפן את build/chunks-view.html. בדקו טקסט מלא, מקור, גרסה ומיקומי הקטע. בשלב הזה עדיין אין וקטור.

4. יצירת embeddings אמיתיים

בחרו אחת משתי הפקודות לפי מסלול ההכנה שלכם.

מקומי:

python build_index.py embed --provider ollama --model embeddinggemma

ענן:

python build_index.py embed --provider voyage --model voyage-3.5 --ask-key

הקוד מציג התקדמות ושומר build/index.json. בשורת הסיכום תראו את מספר המסמכים, הקטעים והממדים. ה־manifest מתעד את הספק, המודל, פורמט הקלט והממדים. במסלול מקומי נשמר גם digest המודל שהותקן.

ההרצה מחשבת מחדש embeddings לכל הקטעים. אם עוברים ספק או מודל, מריצים את שלב embed מחדש לכל הקטעים. הקובץ החדש מחליף את build/index.json; שמרו עותק בשם אחר אם ברצונכם להשוות.

5. איפה רואים chunk, מקור ו־embedding?

python inspect_index.py build/index.json --record 1
python inspect_index.py build/index.json --record 1 --full-vector
python inspect_index.py build/index.json --html build/index-view.html
  • FULL CHUNK TEXT מציג את כל טקסט הקטע.
  • METADATA מציג את המקור, ה־Document ID, הגרסה ומצב המסמך.
  • VECTOR_DIMENSIONS מציג כמה מספרים יש בווקטור.
  • VECTOR_PREVIEW_FIRST_8 מציג את שמונת הערכים הראשונים. --full-vector מציג את כולם.

פתחו את build/index-view.html בדפדפן. לכל קטע יש טקסט קריא ופרטים שנפתחים בלחיצה. אפשר לבדוק גם את הווקטור המלא. כדי לבחור רשומה אחרת בטרמינל, החליפו את המספר שאחרי --record.

התוצר נשמר בקובץ מקומי. בשלב הזה אפשר לראות בדיוק מה יעמוד לרשות החיפוש בתרגיל הבא.

שני בונוסים למתקדמים

בונוס 1 — חלוקה שמבינה מבנה של מסמך

שפרו את Chunking כך שכותרת סעיף תישמר עם התוכן שלה וטבלה ארוכה תחולק בין שורות. לכל חלק של הטבלה שימרו את כותרות העמודות, כדי שתנאי P1 ו־P2 יישארו מובנים.

אתגר הבנייה: טקסט שהועתק ככותרת חוזרת כבר אינו span יחיד במקור. הגדירו בנפרד source_text עם המיקומים המקוריים ו־embedding_text הכולל את ההקשר שהוספתם; התאימו את השמירה והבדיקות.

בדיקה: האריכו עותק של טבלת ההסלמה כך שיעבור את מגבלת הגודל. הציגו שכל שורת מידע נשמרה, שהכותרות זמינות בכל חלק ושאפשר לחזור לכל שורה במקור.

למה זה מתקדם? צריך לתכנן ייצוג ששומר גם משמעות מקומית וגם עקיבות למקור, ולהחליט איך לטפל בטבלה הגדולה ממגבלת הקטע.

בונוס 2 — עדכון חלקי של index קיים

הוסיפו אפשרות לקרוא index קודם ולחשב embeddings רק לטקסטים שהשתנו. השתמשו במזהי מקור וב־hash של קלט ה־embedding; הסירו רשומות של קטעים שנמחקו.

אתגר הבנייה: הגדירו מתי מותר להשתמש בווקטור ישן. שינוי ספק, מודל, digest מקומי, מספר ממדים או פורמט הקלט צריך לבטל שימוש חוזר שאינו תואם. שינוי metadata בלבד יכול לעדכן הפניה בלי חישוב חדש, בתנאי שהקלט המדויק למודל נשאר זהה.

בדיקה: השוו שלוש הרצות: ללא שינוי; שינוי פסקה אחת; מחיקת מסמך. הציגו counters עבור קטעים שנשמרו, חושבו מחדש והוסרו. הוסיפו גם בדיקת שינוי מודל שמחייב חישוב מחדש. בדקו מה קורה כאשר פסקה שנוספה מזיזה את מיקומי כל הקטעים שאחריה.

למה זה מתקדם? נדרש לשלב זהות מסמך, תוקף cache, מחיקת מידע ישן ותאימות וקטורים. ספירת קטעים בלבד אינה מוכיחה שהעדכון תקין.

שני הבונוסים הם הרחבות בחירה לאותו תוצר. אין הגשה נפרדת. משך התרגיל עם Claude Code ייקבע לאחר חזרה מעשית בכיתה או עם המרצה.

בדיקת קבצים כשאין ספק embeddings זמין

אפשר לבדוק את מבנה התוצר באמצעות fixture מקומי. הוא יוצר שמונה מספרים מתוך hash של הטקסט לצורכי בדיקת קוד בלבד.

python build_index.py embed --fixture
python inspect_index.py build/offline-index.json --record 1

בפלט וב־manifest כתוב offline_fixture. המספרים במסלול זה אינם embeddings סמנטיים. המסלול המקומי או מסלול הענן נדרשים כדי להשלים את שלב ה־embeddings של התרגיל.

תיעוד טכני ששימש להכנת התרגיל

  • Ollama — /api/embed: בקשה לטקסט או רשימת טקסטים, קבלת embeddings ושליטה בחיתוך קלט.
  • Ollama — embeddinggemma: שם המודל ופקודת ההכנה.
  • Google — EmbeddingGemma model card: פורמט קלט למסמכים וממדי המודל.
  • Anthropic — Embeddings: ההמלצה על Voyage AI.
  • Voyage AI — Embeddings API: מודל embeddings, input_type ומסלול API בענן.
