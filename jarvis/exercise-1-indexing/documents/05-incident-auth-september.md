# תחקיר: דחיית התחברויות לאחר החלפת מפתח חתימה

האירוע והנתונים מומצאים לצורכי למידה. מסמך זה מתאר אירוע עבר בסביבת Atlas Demo.

## מה קרה

בין 10:05 ל־10:27 נדחו 12% מבקשות ההתחברות של tenant בשם Cedar. שיעור הכשל הכולל בכל הארגון היה 2.1%, ולכן הממוצע הכללי הסתיר את חומרת הפגיעה ב־Cedar. רוב השגיאות ב־tenant היו HTTP 401.

## הראיות והסיבה שנמצאה

ספק הזהויות החל לפרסם מפתח חתימה ציבורי חדש בשעה 10:00. דוח האימות הראה דחיות של בקשות שנחתמו במפתח החדש, ואילו Key Cache המשיך להציג את רשימת המפתחות הקודמת. השוואת מזהי המפתחות ותזמוני הרענון ביססה את המסקנה שה־Cache לא התעדכן בזמן.

## הטיפול והאימות

בעל השירות אישר רענון מבוקר של מידע המפתחות. לאחר הרענון שיעור הכשל של Cedar ירד ל־0.4%. הצוות בדק שהשיפור נשמר במשך 20 דקות וששאר ה־tenants נשארו יציבים.

## מה השתנה בעקבות האירוע

נוספה דרישה להציג מדדי התחברות לפי tenant וסוג שגיאה. ההחלטה להחליף את סף ההסלמה הכללי יושמה ב־ESC-001 גרסה 1.1 וב־RB-AUTH גרסה 2.0 בתאריך 2026-10-22.

## שימוש בתחקיר באירוע חדש

תחקיר זה מציע כיוון בדיקה כאשר מופיעות דחיות HTTP 401. כדי לקשור אירוע חדש לאותה סיבה נדרשת השוואה חדשה בין מפתחות ספק הזהויות, Key Cache ונתוני הדחייה. המסמך מתאר את סיבת האירוע בספטמבר בלבד.
