2. בונים את Cosine Similarity

פתחו retrieval.py והשלימו cosine_similarity. חשבו:

dot = sum(query[i] * chunk[i])
query_length = sqrt(sum(query[i] ** 2))
chunk_length = sqrt(sum(chunk[i] ** 2))
cosine = dot / (query_length * chunk_length)

כל הסכומים עוברים על כל הממדים בווקטור. בדקו שמספר הממדים זהה, שהערכים סופיים וששני הווקטורים בעלי אורך חיובי.

בדיקה ידנית קצרה

query = [1, 0]
A = [0.8, 0.6]
B = [1.6, 1.2]

Dot Product(query, A) = 1*0.8 + 0*0.6 = 0.8
Dot Product(query, B) = 1*1.6 + 0*1.2 = 1.6
Cosine(query, A) = 0.8 / (1*1) = 0.8
Cosine(query, B) = 1.6 / (1*2) = 0.8

הווקטור B ארוך פי שניים מ־A, אבל הכיוון שלהם זהה. Cosine Similarity מנטרל את השפעת האורך בדוגמה הזאת. הציון אינו הסתברות שהקטע מספק תשובה נכונה.

3. בונים Top-k

השלימו select_top_k. מיינו מהציון הגבוה לנמוך והחזירו עד k קטעים. בשוויון השתמשו ב־chunk_id בסדר עולה. שימרו את רשימת הקלט ללא שינוי.

Scores: A=0.2, B=0.8, C=-0.1, D=0.5
k=3  →  B, D, A

k=3 פירושו שלושה קטעים, אם יש לפחות שלושה מועמדים. המספר לא קובע כמה מסמכים שונים יופיעו בתוצאה.

שני בונוסים למתקדמים

בונוס 1 — Hybrid Search וחיבור דירוגים

  1. בנו דירוג מילולי מתוך אותם chunks: למשל מספר מילות השאלה שמופיעות בקטע, לאחר פיצול עקבי למילים. בדקו גם חיפוש מדויק של מזהה כגון HTTP 401.
  2. שמרו בנפרד דירוג Semantic Search ודירוג מילולי. הקטעים בשני הדירוגים צריכים להשתמש באותם chunk IDs.
  3. ממשו reciprocal_rank_fusion ב־bonus_ranking.py. תרומת קטע במקום rank היא 1/(60+rank). חברו תרומות וסדרו מחדש.
  4. השוו שלוש שאלות: קוד שגיאה מדויק, ניסוח בעברית שאינו מופיע כלשונו במסמך, ושאלה שדורשת כמה מסמכים. הציגו מה כל דירוג מוצא ומה שילובם משנה.

למה זה מתקדם? צריך לטפל במזהים חסרים, בשוויון ובסולמות ציונים שונים, ואז לבדוק אם השילוב הוסיף ראיה שימושית. הדירוג המילולי הבסיסי בתרגיל אינו מימוש BM25.

בונוס 2 — Reranking ושמירת גבולות המועמדים

ממשו rerank_candidates: קבלו מועמדים שכבר חזרו וציונים חדשים לכל מועמד, שנו את הסדר ושמרו טקסט ומקור. בדיקות הבונוס מספקות ציוני fixture מומצאים.

  1. בדקו מקרה שבו נוהל עדכני שהיה במקום שני עובר למקום הראשון.
  2. דחו ציון שמפנה ל־chunk ID שאינו בין המועמדים, ודרשו ציון לכל מועמד.
  3. בחרו שאלה שהראיה הדרושה לה חסרה ב־Top-3 הראשוני. השוו candidate pools בגודל 3 ו־8, ובדקו האם Reranking יכול בכלל לקבל את הראיה הנדרשת.
  4. כתבו בדיקה ששומרת את הטקסט והמקור ללא שינוי גם אחרי המיון החדש.

למה זה מתקדם? מיון שני אינו יכול לתקן אובדן ראיה בשלב הראשון. נדרשים כיסוי מועמדים, עקיבות ושמירת חוזה הנתונים.

ציוני ה־fixture בודקים את חיבור השלב ואת התנהגותו. הם אינם פלט של reranker חי ואינם מודדים איכות מודל. בתרגיל זה אין הורדה או הפעלה של מודל נוסף.
